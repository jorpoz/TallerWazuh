
En este taller vamos a hacer una prueba de instalación de **wazuh**, pero si lo queremos poner en un entorno real es importante conocer los requisitos de hardware que debe tener la máquina o maquinas donde lo despleguemos. Por ejemplo si lo desplegamos en una única máquina, los requisitos sugeridos por la documentación son:
https://documentation.wazuh.com/current/deployment-options/docker/wazuh-container.html
![[Pasted image 20261001231644.png]]

Para instalar los componentes de **Wazuh** tenemos varias opciones:
- podemos instalarlo directamente en el host, todo en la mísma máquina o en varias, usando **apt/dnf**.
- podemos utilizar MV ya hechas
- podemos utilizar docker para la instalación. A mi es la opción que más me gusta, además porque creo recordar que lo aconsejaron en una charla sobre wazuh que se realizo en RedIRIS. Y dentro de Docker, me parece muy interesante el despliegue en Docker Swarm, que permite que cada componente se pueda ejecutar en un host anfitrión distinto, pudiendo ampliar el número de componentes en función de la carga.

Para el taller, y en mi caso también, he elegido hacer la instalación con docker, en un único host anfitrión.
Docker nos ofrece la posibilidad de hacer una instalación limpia de los servicios, pudiendo empezar de cero en cualquier momento. No nos tenemos que preocupar de la instalación del software que ejecuta wazuh, ni de las dependencias, solo de la configuración. Ademas podemos replicar la instalación en cualquier otro sitio con docker disponible, sabiendo que va a funcionar de la misma forma.

Los agentes los instalaremos en el host anfitrión y en otra máquina. Usaremos máquinas virtuales para la instalación de los hosts a usar. Utilizamos el **VirtualBox** pero cualquier otro entorno debería funcionar de la misma forma.
Dependiendo de los recursos podemos crear  varias máquinas para crear un entorno de pruebas con el que jugar con nuestra instalación de wazuh. Yo con el portátil que tengo como mucho puedo tener a la vez un linux y un windows, y gracias.

## Despliegue Wazuh

Para el despliegue de wazuh nos fijamos en la documentación de su web:
https://documentation.wazuh.com/current/deployment-options/docker/wazuh-container.html

vienen varias opciones de despligue en docker:
- single-node: Se despliega un contenedor por cada componente central de wazuh
- multi-node: Se despliegan contenedores distintos para cada componente, usando varios contenedores para cada componente.

Me gustaría elegir el **multi-node**, pero requiere más recursos y cuando hice las pruebas el portátil no podía con ello, asi que al final me decanté por el **single-node**, pero el proceso es prácticamante identico. Si se dispone de un **docker swarm** el **multi-node** para mi es la mejor opción pudiendo desplegar cada contenedor de cada componente en un nodo del swarm distinto, obteniendo redundancia de los servicios y pudiendo repartir la carga entre varios nodos.
Nosotros elegimos el **single-node**, pero como ya he dicho es los pasos son practicamente los mismos.

Antes de la instalación:
### Docker host requirements
You need to configure your Docker host to run Wazuh correctly on any system that uses a Linux kernel. This includes native Linux distributions and Windows with WSL 2 (Windows Subsystem for Linux version 2).
1. Set `max_map_count` to `262144` on your Docker host. The Wazuh indexer creates many virtual memory areas (VMAs), so the kernel must allow more than the Linux default limit of `65530`. A VMA is a region of memory that lets applications like the Wazuh indexer access files directly from disk as if they were in RAM.
    Note:    On Windows systems using WSL 2, run this command within the WSL 2 environment.
    `sysctl -w vm.max_map_count=262144`

![[Pasted image 20261003010647.png]]
Si lo ponemos en un swarm, se modifica este parámetro en cada nodo que pueda desplegar un Indexer.
`sysctl -w vm.max_map_count=262144`
`echo "vm.max_map_count = 262144" > /etc/sysctl.d/99-wazuh-indexer.conf` 
`sysctl --system`
