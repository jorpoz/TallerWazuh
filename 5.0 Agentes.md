### Securizando la comunicación de los agentes
Queremos que el agente:
- [use una contraseña](https://documentation.wazuh.com/current/user-manual/agent/agent-enrollment/security-options/using-password-authentication.html)
- [confirme la identidad del servidor](https://documentation.wazuh.com/current/user-manual/agent/agent-enrollment/security-options/manager-identity-verification.html)
#### Contraseña.
Modificamos el fichero `config/wazuh_cluster/wazuh_manager.conf` y ponemos `<use_password>yes</use_password>`
```
vim config/wazuh_cluster/wazuh_manager.conf
grep -C5 use_password config/wazuh_cluster/wazuh_manager.conf
```
![Imagen](imagenes/Pasted%20Image%2020261015111409.png)

Necesitamos un fichero `authd.pass` y mapearlo dentro del contenedor.
Modificamos el `docker-compose.yml`
```
vim docker-compose.yml
grep -B2 authd.pass docker-compose.yml
```
![Imagen](imagenes/Pasted%20Image%2020261015111823.png)

Creamos un fichero `authd.pass` en la ruta  `config/wazuh_cluster/` (dentro del contenedor se verá en `/var/ossec/etc/authd.pass`)
```
echo "PasswordAgente-123" > config/wazuh_cluster/authd.pass
chmod 640 config/wazuh_cluster/authd.pass
chown 0:999 config/wazuh_cluster/authd.pass
```
![Imagen](imagenes/Pasted%20Image%2020261015112116.png)

Por último recreamos el servicio: 
```
docker compose -p wazuh -f docker-compose.yml up -d
```
![Imagen](imagenes/Pasted%20Image%2020261015112211.png)

Y revisamos si existe el `authd.pass` donde lo hemos puesto:
```
docker exec  -ti wazuh-wazuh.manager-1 ls -l /var/ossec/etc/authd.pass
docker exec  -ti wazuh-wazuh.manager-1 cat /var/ossec/etc/authd.pass
```
![Imagen](imagenes/Pasted%20Image%2020261015112312.png)
---
#### Confirmación de la Identidad del Servidor
Ya disponemos de un certificado para el servidor **wazuh.manager**, pero lo tenemos que mapear en un sitio nuevo.
Editamos de nuevo el `docker-compose.yml`
```
vim docker-compose.yml
```

Y añadimos a la definición del `wazuh.manager` los montajes:
```
      - ./config/wazuh_indexer_ssl_certs/wazuh.manager.pem:/var/ossec/etc/sslmanager.cert
      - ./config/wazuh_indexer_ssl_certs/wazuh.manager-key.pem:/var/ossec/etc/sslmanager.key
```

Y reiniciamos el servicio
```
docker compose -p wazuh -f docker-compose.yml up -d
```

### Despliegue en linux

Para desplegar el agente, podemos ver una guía en la propia consola de wazuh:
**Agents managemenet** - **summary** - **deploy new agent**
![Imagen](imagenes/Pasted%20Image%2020261006001054.png)

Pero falta la parte de autenticación del servidor.
El certificado estaba emitido para **wazuh.manager**, por lo que es el nombre que tenemos que poner, y para poder resolverlo lo añadimos al `/etc/hosts`
```
openssl x509 -in /software/source/wazuh-docker/single-node/config/wazuh_indexer_ssl_certs/wazuh.manager.pem --noout -text | grep wazuh.manager
echo "10.0.2.15   wazuh.manager" >> /etc/hosts
tail -1 /etc/hosts
```
![Imagen](imagenes/Pasted%20Image%2020261015124733.png)

Descargamos el agente y comprobamos que es correcto
```
curl -s -o wazuh-agent-4.14.8-1.x86_64.rpm https://packages.wazuh.com/4.x/yum/wazuh-agent-4.14.8-1.x86_64.rpm
curl https://packages.wazuh.com/4.x/checksums/wazuh/4.14.8/wazuh-agent-4.14.8-1.x86_64.rpm.sha512
sha512sum wazuh-agent-4.14.8-1.x86_64.rpm
```
![Imagen](imagenes/Pasted%20Image%2020261015124946.png)

Y ejecutamos:
```
WAZUH_MANAGER='wazuh.manager' WAZUH_REGISTRATION_PASSWORD=$'PasswordAgente-123' WAZUH_AGENT_GROUP='Linux' WAZUH_REGISTRATION_CA='/var/ossec/etc/root-ca.pem' rpm -ihv wazuh-agent-4.14.8-1.x86_64.rpm
cp /software/source/wazuh-docker/single-node/config/wazuh_indexer_ssl_certs/root-ca.pem /var/ossec/etc/root-ca.pem
chmod o+r /var/ossec/etc/root-ca.pem
ls -ln /var/ossec/etc/root-ca.pem
```


Si todo ha ido bien lo instala y crea el directorio `/var/ossec/etc` donde ponemos el `root-ca.pem`
![Imagen](imagenes/Pasted%20Image%2020261015125215.png)

y arrancamos el servicio:
```
systemctl enable --now wazuh-agent
systemctl status wazuh-agent
```
![Imagen](imagenes/Pasted%20Image%2020261015125339.png)

Si todo ha ido bien veremos el nuevo agente:
![Imagen](imagenes/Pasted%20Image%2020261006002850.png)

Si ha ido mal se chequea en **server management** - **logs**. Cuidado con el nombre del agente, no puede ser el mismo que el del manager.
```
less /var/ossec/logs/ossec.log
hostname
vim /etc/hostname
hostname wazuh-taller
systemctl restart wazuh-agent
```

### Despliegue en windows
Ya tenemos un agente instalado en el linux, hacemos lo mismo en el windows
![Imagen](imagenes/Pasted%20Image%2020261007224505.png)

Configuramos las opciones:
![Imagen](imagenes/Pasted%20Image%2020261007225325.png)

Nos muestra el comando que tenemos que ejecutar, pero falta la parte del certificado.
```
Invoke-WebRequest -Uri https://packages.wazuh.com/4.x/windows/wazuh-agent-4.14.8-1.msi -OutFile $env:tmp\wazuh-agent
Get-FileHash $env:tmp\wazuh-agent -Algorithm md5
msiexec.exe /i $env:tmp\wazuh-agent /q WAZUH_MANAGER='wazuh.manager' WAZUH_REGISTRATION_PASSWORD='PasswordAgente-123' WAZUH_AGENT_GROUP='Windows' WAZUH_REGISTRATION_CA="./root-ca.pem"
```

Vemos que tal le sienta. Lo ejecutamos en un powershell con los permisos elevados.
![Imagen](imagenes/Pasted%20Image%2020261007231602.png)
Esto tarda un rato.
En lugar de hacerlo en una VM windows, para que vaya más ágil, se puede hacer en el propio portátil

![Imagen](imagenes/Pasted%20Image%2020261008103258.png)
Ejecutamos la instalación. Debería dejar todo en `c:\Program files (x86)\ossec-agent\`
![Imagen](imagenes/Pasted%20Image%2020261008103842.png)

si editamos el `authd.pass` por ejemplo vemos: 
```
type 'C:\Program Files (x86)\ossec-agent\authd.pass' 
```
![Imagen](imagenes/Pasted%20Image%2020261008104142.png)

Nos falta meter el certificado de la CA, lo ponemos en la ruta `c:\Program Files (x86)\ossec-agent\root-ca.pem`
En el linux:
```
cd /software/source/wazuh-docker/single-node/config/wazuh_indexer_ssl_certs/
systemctl stop firewalld
python3 -m http.server 4646
```

En el windows:
```
# Si lo hacemos en el Host anfitrion editamos el fichero de hosts para incluir "127.0.0.1 wazuh.manager"
# Creamos reglas de NAT para los puertos 1515, 1514, 4646
Invoke-WebRequest -Uri http://wazuh.manager:4646/root-ca.pem -OutFile 'C:\Program Files (x86)\ossec-agent\root-ca.pem'
```

![Imagen](imagenes/Pasted%20Image%2020261008111755.png)

Revisamos el fichero de configuración generado.
```
PS C:\Windows\system32> type 'C:\Program Files (x86)\ossec-agent\ossec.conf'
<!--
  Wazuh - Agent - Default configuration for Windows
  More info at: https://documentation.wazuh.com
  Mailing list: https://groups.google.com/forum/#!forum/wazuh
-->

<ossec_config>

  <client>
    <server>
      <address>wazuh.manager</address>
      <port>1514</port>
      <protocol>tcp</protocol>
    </server>
    <config-profile>windows, windows10</config-profile>
    <crypto_method>aes</crypto_method>
    <notify_time>20</notify_time>
    <time-reconnect>60</time-reconnect>
    <auto_restart>yes</auto_restart>
    <enrollment>
      <enabled>yes</enabled>
      <authorization_pass_path>authd.pass</authorization_pass_path>
      <server_ca_path>./root-ca.pem</server_ca_path>
      <groups>Windows</groups>
    </enrollment>
  </client>
```

Vemos esto `<address>wazuh.manager</address>`, pero hay que poder resolverlo, así que, si no lo hemos hecho, primero tenemos que añadirlo al fichero de hosts. Esto no es necesario si hay desplegado un servicio DNS y tenemos bien puesto los registros.
Usamos un notepad con permisos de administrador y añadimos el registro:
```
PS C:\Windows\system32> type 'C:\Windows\System32\drivers\etc\hosts'
# Copyright (c) 1993-2009 Microsoft Corp.
...
#       ::1             localhost
10.0.2.15               wazuh.manager
```
y ya con todo en su sitio levantamos el servicio y vemos si se ve un nuevo agente.
```
net start wazuh
```
